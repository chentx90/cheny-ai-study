# 前后端分离与状态边界（2026-07）

**目的**：停止「前端整包 workspace blob + 补丁路由」的补丁式改法，明确读写边界与模块职责。

---

## 一、分层结构

```
┌─────────────────────────────────────────────────────────────┐
│  views/          UI 展示、用户事件                             │
├─────────────────────────────────────────────────────────────┤
│  hooks/          业务流程编排（usePreprocess、useProjectWorkspace）│
├─────────────────────────────────────────────────────────────┤
│  domain/         纯业务规则（无 React）                        │
│    workspace/    commitPatch — 字段补丁 → 领域 API 映射        │
├─────────────────────────────────────────────────────────────┤
│  api/            HTTP 薄封装（一 endpoint 一函数）             │
└─────────────────────────────────────────────────────────────┘
                              │ REST + revision
┌─────────────────────────────────────────────────────────────┐
│  api/routes/     HTTP、鉴权、Schema 校验                     │
│  project_domain  业务真相源、revision 检查、工作流门禁        │
│  storage.py      唯一 SQL 访问层                              │
└─────────────────────────────────────────────────────────────┘
```

## 二、后端：真相源与 API 映射

| 数据 | 存储表 | 读 | 写 |
|------|--------|----|----|
| 原文/切分策略 | `project_preprocess` | `GET /session` | `PUT /document` |
| 分集 | `episodes` | 同上 / V2 Episode API | V2 Episode API |
| 剧本 | `episodes.script_text` | 同上 / V2 Episode API | V2 Episode API 或类型化兼容命令 |
| 路径/视频默认 | `project_preprocess` | 同上 | `PUT /settings` |
| 素材确认 | `project_preprocess.assets_confirmed` | 同上 | `POST /assets/confirm` |
| 实体卡/提示词/任务 | 独立表 + 文件 | 各自 GET | 各自 POST/PUT |

`GET /session` 只组合读取规范化资源；不存在对应的整包 PUT。ZIP/文件夹导入在后端直接转换为规范化资源。

**revision**：每次 preprocess 写操作递增；客户端必须在 mutating 请求中带当前 `revision`；冲突返回 409，前端刷新 workspace 后重试或放弃陈旧补丁。

## 三、前端：读写规则

### 读（hydration）

- 选中项目 → `GET /api/projects/{id}/session` → `applyWorkspaceResponse`
- 服务端响应为 **唯一真相**；`applyWorkspaceResponse` 会取消待执行的 debounce 保存

### 写（commit）

1. **乐观 UI**：`updateWorkspace(patch)` 仅更新本地 `workspaceRef` + React state
2. **延迟提交**：350ms debounce → `commitWorkspacePatch(projectId, base, patch)`
3. **立即提交**：`syncWorkspacePatch(patch)` — 取消 debounce，立刻 `commitWorkspacePatch`

`commitWorkspacePatch`（`domain/workspace/commitPatch.js`）按字段分组，**顺序**调用：

`document` → `segments` → `scripts` → `settings` → `assets`

脚本写入规则：

- 单集编辑 → `PUT .../segments/{id}/script`
- 多集/进入剧本阶段 → `PUT .../scripts`（批量）

### 禁止

- ❌ `schedulePersist(整个 session)` — 会把组合视图误当写模型
- ❌ 页面卸载时发送无 revision 的整包请求
- ❌ 服务端已返回 workspace 后再 `updateWorkspace` 触发二次保存（应用 `applyWorkspaceResponse`）

## 四、预处理流程（标准路径）

| 用户操作 | 前端 | 后端 |
|----------|------|------|
| 导入文档 | `POST .../documents/upload` → `applyWorkspaceResponse` | `reset_on_document_upload` |
| 生成切分方案 | `POST .../split/suggest`（只读） | 不落库 |
| 应用切分 | `POST .../split` persist → `applyWorkspaceResponse` | `apply_split_persist` |
| 进入剧本处理 | `syncWorkspacePatch({ scripts, scriptValidation })` | `PUT /scripts` |
| 编辑单集剧本 | `updateWorkspace` debounce → 单集 script API | `save_segment_script` |
| LLM 转写 | `POST .../convert` → `saveSegmentScript` → `applyWorkspaceResponse` | 单集 script |

## 五、目录约定（当前 / 目标）

```
frontend/src/
  api/              HTTP 封装（不含路由逻辑）
  domain/workspace/ 补丁分类 + commitPatch
  hooks/            React 编排
  views/            页面

src/ai_video_manager/
  api/routes/       按资源分文件
  project_domain.py 领域服务
  storage.py        持久化
```

后续可演进（见 `docs/05_前端设计逻辑.md`）：`store/` + TanStack Query 替代 hooks 内聚的服务器状态；**不改变**上述 API 边界。
