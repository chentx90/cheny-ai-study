# AI 视频创作管理工具 V2 大重构实施计划

> 文档状态：已执行，完成审计见 `docs/14_V2完成审计与部署记录.md`
> 制定日期：2026-07-18  
> 目标：在保留现有项目数据和可用能力的前提下，将系统重构为完整、可恢复、可追踪的 AI 视频生产平台。  
> 执行原则：对齐需求 -> 实施 -> 验证 -> 偏差检查 -> 清理代码 -> 重启服务 -> 再验证。

## 1. 重构背景

当前系统已具备项目、预处理、素材与实体、提示词、视频任务、API 配置等能力，但长期增量修改形成了以下结构性问题：

1. 前端 `App.jsx`、`ResourceView.jsx` 和多个 Hook 承担过多状态与业务编排。
2. 后端 `storage.py` 同时负责数据库、文件、迁移和业务规则，模块边界不清晰。
3. `project_workspaces` JSON、规范化数据表和项目目录文件形成多个业务真相源。
4. `Episode`、`Script`、`Shot`、`PromptCard` 语义重叠，数据流容易分叉。
5. LLM 模板、调用配置、结果解析、单卡重跑和错误记录未形成统一运行模型。
6. 视频请求、远程任务、下载结果和采用版本未形成完整任务生命周期。
7. 新旧文档要求存在冲突，测试覆盖不足以支撑继续扩展。

本次重构不继续补丁式堆叠功能，而是先统一领域模型和数据边界，再分批替换现有实现。

## 2. 产品目标与边界

### 2.1 产品定位

系统定位为本地部署、项目隔离、人工可控的 AI 视频生产平台，不是单一模型调用界面。

核心价值：

- 从原始内容到视频归档形成连续生产链。
- 每个项目的数据、文件、任务和结果严格隔离。
- 所有关键 AI 操作可配置、可重跑、可追踪、可人工修正。
- 项目刷新、服务重启和任务中断后能够恢复现场。
- 模型供应商、模型名称、模板和生成参数均可替换。

### 2.2 V2 正式业务链

```text
项目
  -> 原始文档
  -> 分集 Episode
  -> 本集剧本
  -> 提示词卡 PromptCard
  -> 实体匹配
  -> 视频任务 VideoTask
  -> 视频候选 VideoOutput
  -> 采用与归档
```

业务定义：

- `Episode` 同时拥有本集原文和本集剧本，不再建立松散的 Script 聚合。
- `PromptCard` 是视频生产意义上的分镜，不再保留独立 `Shot` 领域模型。
- 提示词生成与实体匹配是两个独立步骤，不能在一次 LLM 调用中混合完成。
- 一个提示词卡允许产生多个视频任务和候选结果，最终由用户选择采用版本。
- 提示词卡锁定后，批量重新生成不得覆盖；单卡重跑使用独立模板和上下文。

### 2.3 暂不纳入本轮

- 3D 导演台与 3DGS 编辑器。
- 社区广场、积分商城和公开作品分享。
- 多人实时光标协作。
- 自动剪辑成片和复杂时间线编辑器。
- 无人工确认的全自动 Agent 制片。

这些能力只能在 V2 主链稳定后评估，不能阻塞本轮重构。

## 3. 数据所有权

### 3.1 项目级数据

以下数据必须携带 `project_id`，文件只能存储在对应项目目录：

- 原始文档、分集原文和剧本。
- 项目素材和实体卡素材引用。
- 实体卡、提示词卡及实体匹配关系。
- AI 运行记录、视频任务、生成结果和归档结果。
- 项目级生成参数、页面工作状态和版本记录。

项目文件布局：

```text
projects/{project_id}/
  source/
  assets/
  generated/
  exports/
```

数据库保存文件元数据和相对路径，禁止保存依赖部署机器的绝对路径。

### 3.2 用户级与系统级数据

以下数据不归属于单个项目：

- 用户账户、权限和会话。
- LLM、图片、视频供应商配置。
- 可复用提示词模板及其版本。
- 界面主题和全局显示偏好。

每次 AI 或视频调用必须把实际使用的配置摘要、模型名称、模板版本和参数快照写入项目运行记录，确保项目结果可复现。

## 4. V2 数据模型

| 数据表/聚合 | 主要职责 |
|---|---|
| `projects` | 项目名称、分类、归档状态、版本号 |
| `documents` | 原始文件、解析文本、文件元数据 |
| `episodes` | 顺序、标题、原文、剧本、版本和状态 |
| `project_assets` | 唯一文件记录、SHA-256、类型、尺寸和路径 |
| `entity_cards` | 人物、场景、物品及状态描述 |
| `entity_material_links` | 实体卡引用项目素材，不重复存储文件 |
| `prompt_cards` | 顺序、来源范围、提示词、预期时长、锁定状态 |
| `prompt_card_entity_links` | LLM/人工匹配结果、置信度和来源 |
| `prompt_templates` | 模板名称、分类、当前版本 |
| `prompt_template_versions` | 模板正文、变量说明和历史版本 |
| `ai_runs` | 使用点、输入快照、输出、状态、耗时和错误 |
| `video_tasks` | 请求快照、供应商、模型、远程任务和状态 |
| `video_outputs` | 本地文件、预览信息、采用状态和任务关系 |

### 4.1 PromptCard 必备字段

```text
id, project_id, episode_id, order
title, source_text, source_start, source_end
prompt_text, expected_duration
locked, status, revision
created_at, updated_at
```

提示词卡数量不得由后端写死。LLM 根据剧本和用户设置的预期总时长决定输出数量；后端只校验数据结构、顺序、时长边界和文本有效性。

### 4.2 AI 运行记录

每个 LLM 使用点统一创建 `ai_runs`：

```text
use_case
project_id / episode_id / prompt_card_id
provider_profile_id, model
template_id, template_version
input_snapshot, output_snapshot
status, error_code, error_message
started_at, finished_at, duration_ms
```

允许模型启用思考模式，但不保存、不返回 `thinking` 或推理过程字段，只保留最终业务结果。

## 5. 前端信息架构

左侧导航固定为：

1. 项目管理。
2. 预处理。
3. 资源管理。
4. 视频生成。
5. 提示词管理。
6. 左下角设置。

项目页面使用 URL 作为当前项目和当前页面的正式状态：

```text
/projects
/projects/:projectId/preprocess
/projects/:projectId/resources
/projects/:projectId/video
/projects/:projectId/prompts
/settings
```

刷新页面时从 URL 恢复项目和页面；本地存储只保存折叠、列宽、筛选、主题等 UI 偏好。

### 5.1 前端目录目标

```text
frontend/src/
  app/                  # Router、鉴权、ProjectContext、QueryClient
  features/
    projects/
    preprocess/
    assets/
    entities/
    prompt-cards/
    video-tasks/
    prompt-templates/
    settings/
  shared/
    api/
    components/
    hooks/
    utils/
```

约束：

- TanStack Query 管理服务端状态、缓存失效和请求生命周期。
- UI 本地状态不得复制完整业务对象。
- 页面组件只负责布局和交互，业务动作进入 feature service/hook。
- API 模块按资源拆分，禁止重新建立万能 `workspace` 接口。
- 表单保存成功后必须重新读取服务端结果，避免前端假成功。

### 5.2 视频工作台

视频生成页面保持三列可调宽布局：

| 区域 | 内容 |
|---|---|
| 左列 | 选集、本集剧本、已匹配实体卡 |
| 中列 | 提示词卡、生成/重新生成、锁定、单卡重跑、排序 |
| 右列 | 视频参数、生成确认、任务队列、候选视频、采用与归档 |

提示词卡和剧本区域允许独立调整高度，但设置稳定最小/最大尺寸，避免内容变化导致布局跳动。

## 6. 后端架构

目标目录：

```text
src/ai_video_manager/
  domain/               # 领域模型、枚举、状态转换和业务规则
  application/          # 用例服务和事务边界
  infrastructure/
    db/                 # migration、repository、SQLite 实现
    files/              # 项目文件、哈希去重和媒体信息
    llm/                # LangChain/LangGraph 调用和结构化解析
    video/              # 视频供应商 adapter
  api/
    routes/             # 薄路由
    schemas/            # 请求和响应 DTO
    dependencies/       # 鉴权、事务、项目权限
  workers/              # 持久任务执行、恢复、提交、轮询和下载
```

后端约束：

- 路由不直接执行 SQL，不直接读写项目文件。
- Repository 只负责持久化，不包含 LLM 和视频业务规则。
- Application Service 负责事务、权限和领域编排。
- LLM 全部通过 LangChain/LangGraph，模板正文只能来自模板管理。
- 视频供应商通过统一 Adapter 接口接入，不在路由里判断供应商细节。
- 长任务先持久化再执行，服务重启后能恢复 `queued/processing` 任务。

## 7. 正式生成流程

### 7.1 提示词生成

```text
读取本集剧本
  -> 读取用户选择的提示词模板版本
  -> 读取预期总时长和模型配置
  -> 创建 ai_run
  -> LLM 返回 PromptCard 数组
  -> 校验并保存
  -> 保留已锁定卡片
```

不得写死目标卡片数量，不得内嵌备用提示词。模板变量缺失时应使用明确的空值或默认上下文，不应直接导致输出失败。

### 7.2 单卡重跑

单卡重跑使用独立的 `prompt_card_rerun` 模板，并提供：

- 本集完整剧本。
- 当前卡片来源文本和范围。
- 当前卡片内容。
- 前后相邻卡片。
- 本集已生成卡片摘要。
- 用户本次修改要求。

单卡重跑只更新目标卡片，并创建新版本；不得改动其他卡片。

### 7.3 实体匹配

```text
本集剧本 + 全部提示词卡 + 当前项目实体卡目录
  -> LLM 判断匹配关系
  -> 保存建议关系
  -> 用户人工添加、删除或替换
  -> 保存确认结果
```

匹配关系记录来源 `llm` 或 `manual`。人工修改后不得被普通刷新覆盖。

### 7.4 视频生成

```text
PromptCard
  + 已确认实体素材
  + 用户选择的视频模型和参数
  -> 二级确认
  -> 创建 VideoTask
  -> 后台上传素材
  -> 提交供应商
  -> 轮询
  -> 下载为 VideoOutput
  -> 用户选择采用结果
```

视频请求必须保存完整快照，包括模型、比例、时长、分辨率、参考模式和素材列表。

## 8. 数据迁移策略

本轮采用原地升级、可回滚迁移，不直接删除旧表。

1. 重构前提交代码基线并备份数据库和 `projects/`。
2. 创建带版本号的 V2 新表。
3. 编写可重复执行的数据迁移器。
4. 将旧 segment/script 合并为 episode。
5. 将现有 PromptCard 直接迁移为 V2 分镜生产单元。
6. 将 Shot 关联信息映射到 PromptCard 后停止写入 Shot。
7. 将实体素材路径迁移为 `project_assets` 与 link 关系。
8. 将现有视频任务迁移，并保留原始请求 JSON。
9. 对每个项目执行数量、顺序、文件存在性和引用完整性校验。
10. V2 连续稳定后，单独提交删除旧表和兼容代码。

迁移必须提供：预检、执行、校验、报告和回滚入口。

## 9. 分批实施计划

### Batch 0：基线保护与需求冻结

- [ ] 只提交当前项目目录的代码基线，不纳入相邻项目改动。
- [ ] 备份 SQLite、配置和项目文件。
- [ ] 记录当前 API、数据库表和主流程冒烟结果。
- [ ] 将本文件确立为 V2 实施入口。

验收：当前版本可启动、可登录、可打开项目，备份可恢复。

### Batch 1：领域模型与 API 契约

- [ ] 建立 V2 领域词典和状态机。
- [ ] 定义 Episode、PromptCard、EntityLink、AIRun、VideoTask、VideoOutput。
- [ ] 明确所有 REST API 请求与响应。
- [ ] 删除设计中的 Shot 聚合和万能 workspace 更新接口。

验收：API 契约覆盖完整主链，所有数据都有唯一所有者。

### Batch 2：数据库 V2 与迁移器

- [ ] 拆分 schema migration 与 repository。
- [ ] 创建 V2 表、索引、外键和 revision 字段。
- [ ] 实现旧数据迁移、校验和回滚。
- [ ] 添加迁移测试和真实项目副本演练。

验收：迁移前后项目、分集、实体、提示词卡和任务数量一致，文件引用无丢失。

### Batch 3：后端应用层重构

- [ ] 建立 Project、Preprocess、Asset、Entity、PromptCard、VideoTask 服务。
- [ ] 路由改为调用 Application Service。
- [ ] 拆分 `storage.py`，停止新增门面方法。
- [ ] 引入统一错误码、事务和 revision 冲突处理。

验收：核心 API 契约测试通过，路由层不存在直接 SQL 和文件操作。

### Batch 4：LLM 运行中心

- [ ] 所有 LLM 调用迁移到 LangChain/LangGraph。
- [ ] 所有模板来自提示词管理，不保留内嵌模板。
- [ ] 建立 use case 与模型配置映射。
- [ ] 建立 `ai_runs`、结构化输出校验、超时和错误分类。
- [ ] 分离整集生成、单卡重跑和实体匹配流程。

验收：三个使用点均可独立测试、查看最终请求摘要、追踪运行结果，不返回 thinking。

### Batch 5：前端应用壳与状态边界

- [ ] 引入 React Router 和 TanStack Query。
- [ ] URL 持久化项目与页面。
- [ ] 拆分 App、鉴权、项目上下文和导航。
- [ ] 建立统一请求错误、Toast 和确认对话框。
- [ ] 清除 Hook 之间的回调链和业务对象镜像。

验收：任意项目页面刷新后仍停留在相同项目和页面，浏览器前进后退正确。

### Batch 6：预处理重建

- [ ] 文档导入和项目素材入口统一。
- [ ] 正则切分、自定义通配符、手动切分和时长切分独立实现。
- [ ] 分集原文支持增删改、排序、保存覆盖。
- [ ] 人工选择直接转存或 LLM 转写剧本。
- [ ] 每集剧本独立保存和版本化。

验收：从新项目导入文档到剧本入库全链可操作，刷新不丢失。

### Batch 7：项目素材与实体卡重建

- [ ] 素材上传后按媒体类型自动分类。
- [ ] SHA-256 去重、重命名、预览、筛选和二级确认删除。
- [ ] 人物、场景、物品三列实体管理。
- [ ] 实体卡小素材库只引用项目素材。
- [ ] 本地上传素材自动进入项目素材库并去重。

验收：素材只存一份；重命名同步全部引用；删除受引用素材时给出明确影响。

### Batch 8：视频工作台重建

- [ ] 左侧完成选集、剧本和实体卡展示。
- [ ] 中间完成整集提示词生成、卡片 CRUD、排序、锁定和单卡重跑。
- [ ] 完成独立 LLM 实体匹配和人工增删。
- [ ] 右侧完成视频参数、二级确认、任务和候选结果。
- [ ] 完成视频采用、重试、下载和归档。

验收：完整跑通“本集剧本 -> 提示词卡 -> 实体匹配 -> 视频任务 -> 结果采用”。

### Batch 9：提示词与配置中心

- [ ] 模板分类、增删改查、复制、版本和恢复。
- [ ] 模板变量说明、示例模板和渲染预览。
- [ ] 各 LLM 使用点独立绑定配置。
- [ ] 服务商保持文本输入，兼容 NewAPI/OpenAI 格式。
- [ ] 一个 Key 获取多个模型并支持连通性测试。
- [ ] 视频模型参数选项持久化。

验收：不存在业务代码内嵌提示词；刷新后配置和参数不丢失。

### Batch 10：任务恢复、观测与成本控制

- [ ] 长任务持久队列与服务启动恢复。
- [ ] AI 和视频任务统一状态语义。
- [ ] 增加重试次数、耗时、错误码和请求关联。
- [ ] 支持项目级任务筛选和失败恢复。
- [ ] 记录可用的 token、请求次数和视频生成成本数据。

验收：服务重启后任务不消失，失败原因可定位，重复提交可防止。

### Batch 11：旧代码清理与正式切换

- [ ] 删除 Shot、workspace blob 写入和旧兼容 API。
- [ ] 删除死函数、未使用 Hook、重复 DTO 和失效样式。
- [ ] 统一新文档，标记历史文档不可作为实现依据。
- [ ] 完成 Docker、NAS、Tailscale 和升级部署验证。

验收：代码搜索不存在旧模型入口，数据库和文件只有一个正式写入链路。

## 10. 测试与验证要求

每批至少执行：

```text
后端单元测试
API 契约测试
数据库迁移测试
前端构建与静态检查
Playwright 关键操作测试
Docker Compose 冒烟测试
服务重启恢复测试
需求偏差检查
git diff 清理检查
```

关键端到端场景：

1. 新建项目，刷新后项目和页面保持。
2. 上传文档，完成分集、排序、编辑和保存。
3. 将分集直接转存或 LLM 转写为剧本。
4. 上传项目素材，创建实体卡并建立素材引用。
5. 根据本集剧本生成数量不固定的提示词卡。
6. 锁定部分卡片，重新生成时锁定内容保持不变。
7. 单卡重跑只生成目标卡片的新版本。
8. LLM 匹配实体后进行人工添加和删除。
9. 设置模型、比例、时长和分辨率并提交视频。
10. 服务重启后继续同步任务并下载结果。
11. 从多个候选中选择采用结果并归档。

## 11. 提交与回滚纪律

- 每个 Batch 使用独立提交，提交信息包含 Batch 编号。
- 禁止一次提交同时重构多个未完成业务域。
- 数据迁移提交必须附带回滚和校验测试。
- 新实现验收前保留旧读取能力，但禁止新旧两套同时写入。
- 删除旧代码必须放在正式链路验证之后。
- 不得提交真实 API Key、运行数据库、生成视频和项目私有素材。
- Git 根目录包含相邻项目时，只暂存本项目路径。

## 12. 完成标准

- 六个导航入口职责明确，无重复业务页面。

- Episode -> PromptCard -> EntityLink -> VideoTask 数据链可追踪。

- 刷新、浏览器重开、前后端重启后业务状态可恢复。

- 旧 workspace blob、重复 API 和死代码已清理。
- 文档、测试、部署配置与实际实现一致。
