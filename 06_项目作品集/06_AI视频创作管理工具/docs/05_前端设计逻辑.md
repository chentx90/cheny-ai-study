## 一、现有前端问题清单

### F-1【数据丢失】`updateWorkspace` 存在闭包竞态

所有写操作都走 `updateWorkspace(patch)`，它基于闭包里的旧 `workspace` 合并：

```js
async function updateWorkspace(patch) {
  const nextWorkspace = { ...workspace, ...patch };  // workspace 是渲染时快照
  setWorkspace(nextWorkspace);
  await persist(nextWorkspace);
}
```

用户快速连点两个实体确认时，第二次的 `workspace` 还是第一次更新前的快照 → 第一次的确认被覆盖丢失。且每次点击都整包 PUT 全量 workspace，先发出的请求可能后到达（后端最后写入者获胜），进一步放大丢失概率。

**修复**：
```js
const workspaceRef = useRef(workspace);
function updateWorkspace(patchOrFn) {
  setWorkspace((prev) => {
    const next = typeof patchOrFn === 'function' ? patchOrFn(prev) : { ...prev, ...patchOrFn };
    workspaceRef.current = next;
    schedulePersist(next);            // debounce 500ms + 序列化队列，禁止并行 PUT
    return next;
  });
}
```
持久化用"单飞行 + 尾随合并"策略：同一时间最多一个 PUT 在途，期间新变更合并到下一次。

### F-2【功能失效】项目分类过滤逻辑是坏的

`category` 存在 workspace（每个项目自己的工作区数据）里，但过滤时只有"当前选中项目"能拿到自己的 category，其他项目一律 `return true`：

```js
const filteredProjects = projects.filter((project) => {
  if (projectFilter === 'all') return true;
  if (selectedProject?.id === project.id) return workspace.category === projectFilter;
  return true;   // ← 非选中项目永远通过，过滤同虚设
});
```

**修复**：分类是项目属性，不是工作区状态。`category` 上移到后端 Project 模型（`PUT /api/projects/{id}` 支持改 category），项目列表接口直接返回，前端按 `project.category` 过滤。

### F-3【安全】API Key 明文回显

`SettingsView` 用 `defaultValue={apiConfig.llmApiKey}` 把密钥填回 password input。配合后端修复（review 文档 P1-8），前端改为：占位符显示 `已配置 (sk-***abcd)`，输入框留空表示不修改，只有用户输入新值才提交该字段。

### F-4【流程断裂】实体确认、提示词、视频生成之间没有数据链路

- 实体 `confirmed` 状态改完后没有任何下游使用（不影响提示词、不阻断生成）；
- `renderPrompt` 只用固定的第一个 video_generate 模板，用户无法选择模板；
- `generatePreview` 之后没有"完整生成"入口 —— canvas 的核心流程"预览满意 → 完整生成"断在一半；
- 没有实体库（EntityCard）界面，提取出的实体无法绑定素材，视频生成请求的 `assets` 永远是空的。

### F-5【一致性】draftPrompt 切换片段时静默丢弃未保存的编辑

`PromptView` 的 `useEffect` 在 `activeSegment.id` 变化时直接用 `activePrompt` 覆盖 `draftPrompt`，用户编辑一半切换片段，编辑内容无提示丢失。修复：切换前检测 `draftPrompt !== activePrompt`，弹确认或自动保存。

### F-6【结构】900 行单文件 + 全局 busy 字符串

- 所有组件、工具函数、API 调用挤在 `main.jsx`；
- `busy` 是单个字符串，意味着全局同时只能有一个操作在途（切分时不能刷新项目列表）；
- `notice` 单条消息，错误和成功共用一个槽位，且被 subtitle 复用，第二个操作会冲掉第一个的错误信息。

## 二、目标前端架构

### 2.1 文件结构（重构目标）

```
frontend/src/
├── main.jsx                  # 仅挂载 <App/>
├── api/
│   └── client.js             # request 封装、错误规范化、API_BASE
├── store/
│   ├── useProjectStore.js    # 项目列表/当前项目（Zustand）
│   ├── useWorkspaceStore.js  # 工作区状态 + debounce 持久化队列
│   └── useConfigStore.js     # 模板、API 配置、全局开关
├── views/
│   ├── ProjectsView.jsx
│   ├── PreprocessView.jsx    # 文本管理界面（canvas: 文本管理）
│   ├── EntityLibraryView.jsx # 实体库管理界面（canvas: 实体库，当前缺失）
│   ├── ResourceView.jsx      # 实体提取与确认
│   ├── PromptsView.jsx
│   ├── VideoView.jsx         # 生成 + 归档 + 版本对比
│   └── SettingsView.jsx
├── components/
│   ├── WorkflowStepper.jsx   # 全局流程进度条（canvas: 进度追踪）
│   ├── SegmentList.jsx
│   ├── EntityCardEditor.jsx
│   ├── ConfirmGate.jsx       # 人工确认门组件（自动同意开关感知）
│   └── ui/                   # Panel/Metric/Empty/Toast 等
└── styles.css
```

### 2.2 状态分层

| 层 | 内容 | 存放 | 持久化 |
|----|------|------|--------|
| 服务器状态 | 项目列表、模板、实体库、任务状态 | TanStack Query（或轻量 SWR 模式） | 后端 |
| 工作区状态 | 文本、片段、脚本、提示词、实体确认 | useWorkspaceStore | debounce PUT workspace |
| UI 瞬时状态 | 当前视图、选中片段、表单草稿 | 组件本地 state | 不持久化 |
| 全局配置 | autoApprove、离线模式 | useConfigStore | 后端 config |

关键规则：**任务状态（videoTasks）从工作区状态中移出**，改为服务器状态轮询获取——生成任务是后端长任务，前端存快照必然过期。

## 三、各界面具体交互逻辑

### 3.1 全局：工作流步骤条（WorkflowStepper）

常驻顶栏，渲染 canvas 主流程的 9 个状态：

```
文档输入 → 切分 → 剧本转换 → 实体提取 → 实体绑定 → 提示词 → 素材确认 → 生成 → 归档
```

数据源 `GET /api/projects/{id}/state`。逻辑规则：

1. 已完成状态：绿色勾，**可点击** → 跳到对应视图（"从任意节点往下走"）；
2. 当前状态：高亮 + 进行中动画；
3. 未来状态：灰色；若 `can_jump_to` 返回 true（前置信息足够）则显示"可跳转"样式，点击直达；
4. hover 未满足的状态时，展示 `missing_prerequisites` 返回的缺失项（如"缺少：脚本"），指引用户去补。

### 3.2 预处理视图（文本管理界面）

**布局**：左（原文编辑）/ 中（片段列表）/ 右（脚本预览），维持现有三栏。

**新增交互逻辑**：

1. **切分建议模式**（对应 canvas「AI智能切分建议」）：
   - 点击"切分"不再直接执行，而是调 `POST /api/documents/split/suggest`，弹出对比面板：三种策略各自的片段数、每片段首行摘要、预估时长；
   - 用户选定方案后才真正落盘；勾选"下次直接使用此策略"则跳过建议步骤。
2. **切分是破坏性操作的防护**：当前代码切分会清空 scripts/entities/prompts/videoTasks。重切分前必须弹确认框列明将被清除的内容数量（"将清除 3 个脚本、12 个实体、2 个提示词"），并先自动保存检查点。
3. **逐片段转换 + 合格标记**：现有"生成脚本"是全量串行。改为：
   - 每个片段行内有独立"转换"按钮 + 状态徽章（未转换/转换中/已转换/不合格）；
   - "全部转换"用受控并发（同时 2 个），单片段失败不中断其他；
   - 脚本预览面板从只读改为可编辑（人工修正后标记"已人工确认"），底部有"不合格，重新转换"按钮 → 对应 canvas 的转换质检环路。

### 3.3 实体库视图（EntityLibraryView，新增）

canvas 的核心界面，当前完全缺失。

**布局**：左侧实体卡片列表（按 角色/道具/场景 分组 + 搜索），右侧卡片编辑器。

**卡片编辑器逻辑**：
1. 卡片标识 = `实体名 · 状态`（如「小明·幼年」），同名实体不同状态是独立卡片，列表中按实体名聚合折叠；
2. 三类素材槽：参考图（多张，缩略图网格）、声音样本、参考视频；本地文件选择后上传到 `projects/{id}/assets/`，卡片存相对路径；
3. "组合生成新状态卡"：选择现有卡片 → 复制素材 → 修改状态名（对应 canvas「组合生成实体卡」）；
4. 场景模板包导入：从模板库一键导入预配置卡片组。
5. **图片服务（Nova）**：设置仅开关内置 Nova；模型/Key 在 Nova 内配置；侧栏「生图」嵌入 `/__nova`；成品可选入库。

### 3.4 资源视图（实体提取与绑定确认）

重构现有 ResourceView，补齐绑定链路：

1. 点"提取实体" → 提取结果表格，每行显示：实体名 / 类型 / 状态 / **绑定建议**；
2. 绑定建议列调 `POST /api/entities/smart-bind`，显示 top-1 候选卡片和置信度（如「小明·青年 92%」），下拉可换其他候选或"新建卡片"；
3. 行级操作：确认绑定 / 修改绑定 / 删除实体 / 跳转实体库编辑该卡片；
4. **确认门（ConfirmGate）逻辑**：
   - `autoApprove=false`（默认，质量优先）：必须逐个或批量点击确认，全部确认后"下一步"才可用；
   - `autoApprove=true`：置信度 ≥ 阈值（默认 0.85）的自动标记已确认，低于阈值的仍然强制人工处理——自动同意不等于放过低置信度项；
   - 顶部常驻当前模式提示（"质量优先模式：需人工确认全部绑定"）。

### 3.5 提示词视图

1. 模板选择从"固定取第一个"改为显式下拉（按 category 过滤），记住每片段最近使用的模板；
2. 渲染前展示模板变量表单：`script` 自动注入，其余变量（如 style）用户填写；
3. 生成结果可编辑，保存时若内容与模板渲染结果不同，标记"已人工修改"徽章（版本对比时有用）;
4. 片段切换时未保存草稿 → 弹「保存/丢弃」确认（修复 F-5）；
5. 模板表单校验：提交前在前端解析 `{}` 占位符并与 variables 字段比对，不一致直接报错（与后端 P1-5 校验对应）。

### 3.6 视频生成视图（对应 canvas 生成与归档界面）

流程重排为四段，从上到下即生成生命周期：

1. **生成输入区**：片段 + 提示词 + 绑定素材清单（只读汇总，列出将上传的实体卡素材文件）。素材确认状态未通过时整个区域禁用，显示"请先完成素材确认"；
2. **成本闸门**：
   - 「4 秒预览」永远可用（低成本验证）；
   - 「完整生成」按钮默认禁用，仅当该片段存在至少一次预览任务、或用户显式勾选"跳过预览直接生成"时启用——把"重付费、要质量"落成 UI 强制习惯；
   - 点击完整生成时二次确认弹窗：显示时长、片段数、（如后端可估）预计费用。
3. **任务队列区**：任务状态由前端每 5s 轮询 `GET /api/videos/tasks?project_id=`（不再存 workspace）。状态流：pending → processing（进度条）→ completed（内嵌播放器预览）/ failed（错误原因 + 重试按钮）；**重试**打开与「生成视频请求」同构的弹窗，预填该任务的提示词与模型/比例/参考参数，确认后以 `POST /api/videos/tasks/{id}/retry` 带覆盖字段创建新版本。
4. **归档与版本区**：按片段分组展示历史任务（v1, v2…），支持两个版本并排播放对比；"回溯重发"按钮把旧任务的 prompt/assets 复制回生成输入区供调整后重发（对应 canvas「回溯到请求前状态」）。

**中栏提示词卡片（`PromptCardPanel` / `VideoPromptCard`）**

1. **布局**：左栏剧本、中栏按片段纵向滚动的提示词卡片列表、右栏任务与预览；列宽由 `.video-column-resizer` 拖拽，高度偏好写入 `localStorage`（`videoUiPrefs`）。
2. **卡片高度**：禁用浏览器原生 `resize: vertical`（避免 ↕ 把手叠到邻卡标题栏）；仅在右下角 20px 热区响应拖拽，`clampPromptCardHeight` 限制 280px～约 92vh，松手后按 `cardId` 持久化。
3. **标题栏**：「分镜内容」保持左对齐；版本标签（当前 / 重跑 / 手工）居中 tab 样式；右侧下载与字号控件。
4. **操作区**：生成、保存、重跑、锁卡等按钮固定在卡片底部 `prompt-card-footer`，不与顶栏混排。

### 3.7 设置视图

1. API Key 处理见 F-3；
2. **流程预检卡片**（canvas「预检系统」）：调 `POST /api/config/precheck`，逐项显示 LLM 配置 / 视频 API 配置 / 模板可用性 / 磁盘空间 的通过状态，任何一项失败在其他视图顶部显示黄色警告条；
3. 全局开关分组展示，每个开关下方一行灰字说明后果（如"自动同意：置信度≥0.85 的实体绑定将跳过人工确认"）。

## 四、通用交互规范

1. **错误提示**：`notice` 单字符串改为 toast 队列（成功 3s 自动消失，错误常驻需手动关闭），错误信息保留后端 detail；
2. **并发控制**：`busy` 字符串改为 `Set<string>`，不同面板的操作互不阻塞，同一操作防重复提交；
3. **确认弹窗三原则**：破坏性操作（重切分/删除卡片/覆盖工作区）必须确认；确认框必须量化影响（"将清除 N 个 X"）；付费操作必须显示成本信息；
4. **空状态引导**：每个视图的空状态给出"上一步该做什么 + 跳转按钮"，而不是只显示"暂无数据"；
5. **本地兜底**：后端 health 失败时进入只读模式，展示缓存的最后工作区快照，禁用全部写操作按钮并显示离线横幅。
