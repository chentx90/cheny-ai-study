# 存储与索引适配器模块

## 一、模块定位

存储与索引适配器模块负责屏蔽不同数据库、搜索引擎、向量库、图数据库之间的差异，为上层召回策略提供统一能力。

上层策略不直接调用 PostgreSQL、OpenSearch、Qdrant、Neo4j，而是调用统一适配器能力。

## 二、核心原则

```text
数据库只注册能力，不绑定场景
召回策略只声明能力，不指定数据库
适配器负责把抽象请求翻译为具体数据库查询
同一个能力可以由多个后端提供
同一个后端可以提供多个能力
```

## 三、能力模型

统一能力类型：

```text
vector_search        向量检索
keyword_search       关键词检索
bm25_search          BM25 检索
metadata_filter      元数据过滤
chunk_fetch          Chunk 取回
parent_expand        父文档/相邻块扩展
asset_fetch          图片/附件取回
data_asset_search    数据资产检索
entity_search        实体检索
graph_expand         图谱扩展
rerank_score         精排打分
log_write            检索日志写入
```

## 五、统一查询请求

### 1. 向量检索请求

```json
{
  "capability": "vector_search",
  "query": "液压泵压力不足怎么办？",
  "query_embedding": [0.01, 0.02],
  "top_k": 10,
  "filters": {
    "business_domain": "equipment",
    "status": "active"
  }
}
```

### 2. 关键词检索请求

```json
{
  "capability": "bm25_search",
  "query": "液压泵 压力不足 过滤器",
  "top_k": 10,
  "filters": {
    "business_domain": "equipment"
  }
}
```

### 3. 父文档扩展请求

```json
{
  "capability": "parent_expand",
  "chunk_ids": ["chunk_001", "chunk_002"],
  "expand_mode": "neighbor",
  "window": 1
}
```

### 4. 图片资产取回请求

```json
{
  "capability": "asset_fetch",
  "chunk_ids": ["chunk_001"],
  "asset_types": ["image"]
}
```

## 七、PostgreSQL + pgvector 适配器

支持能力：

```text
vector_search
metadata_filter
chunk_fetch
parent_expand
asset_fetch
data_asset_search
log_write
```

适用场景：

```text
学习阶段主数据库
文档 Chunk 向量检索
数据资产检索
图片 URL 返回
父文档相邻块扩展
检索日志
```

## 八、OpenSearch 适配器

支持能力：

```text
keyword_search
bm25_search

```

适用场景：

```text
关键词精确召回

```

## 十二、适配器容器化

每类适配器可以单独容器化：

```text
adapter-postgres
adapter-opensearch
adapter-qdrant
adapter-graph
adapter-object
```

第一阶段可以把适配器合并在 `rag-service` 内部，后续按数据库类型拆出独立容器。

## 十三、配置驱动组合

检索策略通过配置选择候选后端。

```yaml
backends:
  postgres_pgvector:
    capabilities:
      - vector_search
      - parent_expand
      - asset_fetch

  opensearch_main:
    capabilities:
      - bm25_search

strategies:
  hybrid:
    required:
      - vector_search
      - bm25_search
    candidates:
      vector_search:
        - postgres_pgvector
        - qdrant_main
      bm25_search:
        - opensearch_main
```

## 十四、总结

存储与索引适配器模块的价值在于：

```text
上层策略不用关心数据库细节
底层数据库可以独立替换
同一策略可组合多个后端
同一后端可服务多个策略
```

它是实现“每个数据库都能与每个召回方式任意组合”的关键中间层。
