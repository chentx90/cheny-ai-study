# 检索编排构件设计说明书

## 一、构件定位

接收用户查询，选择检索方法，按步骤执行算子，组合多路证据返回结构化结果。

不直接写数据库，只读 `active` 状态的知识单元。

---

## 二、检索链路

```text
POST /api/retrieve
  │
  ▼ method_resolver.resolve_method()
  方法 ID 确定（优先级：显式 method > 显式 mode > intent 推断 > 默认）
  │
  ▼ method_loader.load_method()
  从 methods/*.json 加载 RetrievalMethod（steps 列表）
  │
  ▼ ExecutionEngine.run(method, context)
  for step in method.steps:
    operator = registry.get_operator(step.operator)
    results = await operator.execute(context)
    context.merge(results)
  │
  ▼ 返回 KnowledgePackage
  {
    evidence:    List[EvidenceItem],     # 文本块
    assets:      List[AssetItem],        # 图片/附件
    data_assets: List[DataAssetItem],    # 结构化数据
    trace:       List[TraceStep],        # 每步执行记录
  }
```

---

## 三、方法选择优先级

```text
1. 请求体携带 method_id    → 直接使用
2. 请求体携带 mode         → 查 STRATEGY_CATALOG 映射
3. 无 mode，有 query       → detect_intent() 推断 business_domain
                             → 按 domain 选默认方法
4. 兜底                   → document_vector_v1
```

## 四、检索方法配置（JSON）

每个方法是一个独立 JSON 文件，放在 `backend/app/methods/`：

```json
{
  "method_id": "equipment_troubleshooting_v1",
  "description": "设备故障排查：向量召回 + 父块扩展",
  "steps": [
    {
      "name": "chunk_vector",
      "operator": "vector_search",
      "backend": "postgres_pgvector",
      "params": { "top_k": 5, "business_domain": "equipment" }
    },
    {
      "name": "parent_expand",
      "operator": "parent_expand",
      "backend": "postgres_pgvector",
      "params": { "expand_ratio": 0.3 }
    },
    {
      "name": "asset_fetch",
      "operator": "asset_fetch",
      "backend": "postgres_pgvector",
      "params": {}
    }
  ]
}
```

## 五、算子清单

| 算子 | 文件 | 功能 |
|:--|:--|:--|
| `vector_search` | `operators/vector_search.py` | pgvector `<=>` 余弦距离，返回 top-k chunks |
| `parent_expand` | `operators/parent_expand.py` | chunk → parent_doc 展开，补充上下文 |
| `asset_fetch` | `operators/asset_fetch.py` | 关联 chunk 的图片/附件资产 |
| `data_asset_search` | `operators/data_asset_search.py` | 结构化数据资产向量检索 |

算子接口契约：

```python
class BaseOperator:
    async def execute(self, context: ExecutionContext) -> OperatorResult: ...
```

## 六、核心类型（`core/schemas.py`）

```python
class RetrieveRequest:
    query: str
    method_id: str | None
    mode: str | None
    constraints: dict          # business_domain / top_k 等过滤条件

class KnowledgePackage:
    evidence:    list[EvidenceItem]
    assets:      list[AssetItem]
    data_assets: list[DataAssetItem]
    trace:       list[TraceStep]

class ExecutionContext:
    query: str
    method: RetrievalMethod
    pool: asyncpg.Pool
    constraints: dict
    results: dict              # 各 step 结果暂存
```

## 八、向量检索细节

索引：HNSW + 余弦距离（`vector_cosine_ops`）

```sql
SELECT id, content, summary, 1 - (embedding <=> $1::vector) AS score
FROM kb_chunks c
JOIN kb_documents d ON c.doc_id = d.id
WHERE d.status = 'active'
  AND ($2::text IS NULL OR d.business_domain = $2)
ORDER BY embedding <=> $1::vector
LIMIT $3;
```

Embedding 当前为 MockEmbeddingService（SHA256 seed + numpy random，1536维）；
替换真实模型时只需实现相同 async 接口，无需改算子代码。

## 九、扩展点

| 扩展场景 | 做法 |
|:--|:--|
| 新增检索方法 | 在 `methods/` 下新增 JSON，无需改代码 |
| 新增算子 | 实现 `BaseOperator.execute()`，在 `registry.py` 注册 |
| 接入新数据库（Qdrant / Milvus） | 实现 `BaseAdapter`，注册新 backend_id |
| 替换 Embedding 模型 | 实现 `BaseEmbeddingService`，修改 `config.EMBEDDING_MODEL` |
| Rerank | 新增 `rerank` 算子，插入到 steps 末尾 |

## 十、关键约束

- **只读 active**：所有检索 SQL 均加 `WHERE d.status = 'active'`，归档文档不参与检索。
- **无写操作**：检索链路不写任何数据库表（日志除外）。
- **Trace 透明**：每步算子耗时、输入/输出 chunk 数记入 `trace`，前端实验台可展示。
- **单池**：`ExecutionContext` 传入共享 pool，算子不自建连接。
