# 召回策略模块

## 一、模块定位

召回策略模块负责定义和执行不同 RAG 检索方法。

它不直接绑定数据库，而是声明自己需要哪些能力，再由检索计划和索引适配器选择具体后端执行。

## 二、策略执行原则

```text
策略声明能力需求
Planner 选择可用后端
Adapter 执行具体查询
Runtime 负责融合和排序
```

例如 Hybrid 策略不指定使用 PostgreSQL 或 OpenSearch，而是声明：

```text
需要 vector_search
需要 bm25_search
需要 score_fusion
```

由系统配置决定：

```text
vector_search 使用 pgvector 或 Qdrant
bm25_search 使用 OpenSearch 或 PostgreSQL ILIKE 模拟
```

## 三、策略清单

### 1. simple_vector

能力需求：

```text
vector_search
metadata_filter
```

用途：

```text
普通语义检索
文档问答
数据资产语义匹配
```

输入：

```json
{
  "query": "液压泵压力不足怎么办？",
  "top_k": 10,
  "filters": {
    "business_domain": "equipment"
  }
}
```

输出：

```text
候选 Chunk 或数据资产
```

### 2. preset_question

能力需求：

```text
vector_search 或 keyword_search
```

用途：

```text
用户问法和原文表达差异较大时增强匹配
```

实现方式：

```text
方案 A：preset_questions 拼接进 embedding_text
方案 B：preset_questions 单独建向量索引
方案 C：preset_questions 进入关键词索引
```

第一阶段可使用方案 A，后续拆为独立问题索引。

### 3. parent_context

能力需求：

```text
vector_search
chunk_fetch
parent_expand
```

用途：

```text
命中 Chunk 后补充前后文
长文档问答
制度条款解释
```

执行流程：

```text
向量召回 top chunks
  ↓
按 document_id + chunk_index 找相邻 Chunk
  ↓
按窗口大小合并上下文
  ↓
返回扩展后的证据包
```

### 4. image_context

能力需求：

```text
vector_search
asset_fetch
```

用途：

```text
设备图、流程图、截图、说明书图片证据
```

执行流程：

```text
召回 Chunk
  ↓
读取 Chunk 的 image_refs 或 chunk_id
  ↓
获取图片 URL、caption、OCR、description
  ↓
随文本证据返回
```

### 5. data_asset

能力需求：

```text
vector_search
metadata_filter
data_asset_search
```

用途：

```text
智能问数前匹配指标、表、字段、案例、工具
```

返回分组：

```text
metric
table
column
case
tool
```

供 DataAgent 生成 SQL 或选择工具。

### 6. keyword / bm25

能力需求：

```text
keyword_search
bm25_search
```

用途：

```text
型号、编号、制度条款、精确术语检索
```

可由：

```text
OpenSearch
Elasticsearch
PostgreSQL ILIKE / full text search
```

提供。

### 7. hybrid

能力需求：

```text
vector_search
keyword_search 或 bm25_search
score_fusion
```

用途：

```text
兼顾语义召回和关键词召回
```

执行流程：

```text
向量召回
  +
关键词召回
  ↓
去重
  ↓
RRF 或加权融合
  ↓
返回候选结果
```

融合方式：

```text
RRF
weighted_score
max_score
```

### 8. rerank

能力需求：

```text
candidate_recall
rerank_model
```

用途：

```text
候选集精排
高可靠问答
复杂语义判断
```

执行流程：

```text
先召回 top_n 候选
  ↓
将 query + candidate 送入 reranker
  ↓
按 rerank_score 排序
  ↓
返回 top_k
```

### 9. graph_rag

能力需求：

```text
entity_search
graph_expand
chunk_fetch
```

用途：

```text
实体关系推理
设备故障链路分析
指标血缘查询
```

执行流程：

```text
抽取 query 实体
  ↓
实体检索
  ↓
图谱扩展
  ↓
找到相关文档 / Chunk / 数据资产
  ↓
返回关系证据包
```

### 10. crag

能力需求：

```text
candidate_recall
evidence_evaluate
retry_plan
```

用途：

```text
判断召回证据是否足够
不足时补充检索或改写问题
```

执行流程：

```text
初次召回
  ↓
证据评估
  ↓
判断 correct / ambiguous / incorrect
  ↓
必要时重写查询并再次召回
```

## 四、策略组合

策略可以组合成检索管线：

```json
{
  "pipeline": [
    "simple_vector",
    "keyword",
    "hybrid_fusion",
    "parent_context",
    "image_context",
    "rerank"
  ]
}
```

也可以按查询类型选择：

| 查询类型 | 推荐策略组合 |
|:--|:--|
| 普通问答 | simple_vector |
| 专业术语/编号查询 | keyword / bm25 |
| 设备故障 | hybrid + parent_context + image_context |
| 制度条款 | hybrid + parent_context + rerank |
| 智能问数 | data_asset |
| 高可靠回答 | hybrid + rerank + crag |
| 关系推理 | graph_rag + parent_context |

## 五、策略不绑定接口

策略模块不预设固定 HTTP 路径，如 `/rag/simple-vector` 必须对应某个实现。

更推荐使用统一入口：

```text
POST /retrieve
```

请求中声明：

```json
{
  "query": "液压泵压力不足怎么办？",
  "mode": "balanced",
  "requested_strategies": ["hybrid", "parent_context", "image_context"],
  "filters": {
    "business_domain": "equipment"
  }
}
```

也可以由 Agent 不传 `requested_strategies`，让 Planner 自动决定。

## 六、容器化设计

容器名称：

```text
retriever-runtime
```

职责：

```text
执行召回策略
调用索引适配器
结果融合
去重
排序
上下文扩展
返回候选证据
```

不负责：

```text
文件解析
数据库底层查询细节
Agent 最终回答
```

## 七、总结

召回策略模块只描述“怎么召回”，不描述“从哪个数据库召回”。

关键原则：

```text
策略能力化
数据库后端可替换
策略之间可组合
查询时动态规划
接口不钉死
```
