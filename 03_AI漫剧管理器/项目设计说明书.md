# AI漫剧管理器 - 项目设计说明书

> 版本: v3.1 | 日期: 2026-06-14 | 状态: Demo完成
> 技术栈: Python 3.14 + LangChain + LangGraph + Git + JSON文件存储

---

## 一、项目定位

CLI 工具，实现：**小说 → 剧本 → 分镜 → 人物/场景/道具提取 → 提示词生成** 的核心链路。
Git 管理版本，LangGraph 编排 AI 工作流，JSON 文件存储所有数据。

### 技术选型

| 用途 | 库 | 说明 |
|------|-----|------|
| CLI | **Typer + Rich** | 声令式命令 + 美化终端 |
| LLM | **LangChain + NewAPI** | 统一 OpenAI 兼容接口中转 |
| Agent | **LangGraph** | 状态机编排多步 AI 流程 |
| 存储 | **JSON 文件** | 每项目一个文件夹，人可读 |
| 版本 | **Git** (subprocess) | 每次操作自动 commit |
| 提示词 | **prompts.py** (str.format) | 集中管理，按项目复制可特化 |

```
│   │   ├── prompts.py                 # 提示词默认模板 (init 时复制到项目)

│   │   └── nodes/
│   │       ├── split.py              # 长篇分集 (比例+边界定位)
│   │       ├── convert.py             # 小说→分镜 (chunk并发)
│   │       ├── extract.py             # 提取人物/场景/道具
│   │       ├── bind.py                # 绑定 (字符串匹配 + LLM精确)
│   │       └── infer.py               # 推理图片/视频提示词 (并发+锚定)
│   └── version/
│       └── vcs.py                     # Git封装
│
└── data/                              # 运行时数据 (git忽略)
    ├── .active                        # 当前活动项目 id (drama use 写入)
    └── projects/
        └── {project_id}/
            ├── project.json           # 项目元数据 (id/name/style/created_at)
            ├── prompts.py             # 提示词副本 (init 时复制, 可按项目特化)
            ├── episodes.json          # 分集列表 (index=0 为大纲)
            ├── panels.json            # 分镜列表
            ├── entities.json          # 实体列表 (含 importance/image_path)
            ├── bindings.json          # 分镜-实体绑定 {panel_id:[entity_id]}
            ├── variables.json         # 变量配置 (画风/负面词/分集方案)
            ├── operations.jsonl       # 统一操作日志 (每行一条 JSON)
            ├── export/                # 导出的图片/视频提示词 (drama export)
            └── media/                 # 媒体文件
```

> 提示词模板源文件: `src/drama_manager/llm/prompts.py`（默认模板，也是兜底）。
> `drama init` 时复制一份到 `data/projects/{id}/prompts.py`，运行时优先加载项目副本，
> 用户可按项目特点修改自己的副本，不影响默认模板，各项目互不干扰。

## 三、数据结构

### 3.1 project.json

```json
{
  "id": "demo",
  "name": "示例项目 - 妹妹人生",
  "source_text": "原文全文（可选，--file 直接分集时为空）",
  "style": "电影感动画",
  "created_at": "2026-06-14T10:00:00"
}
```

> 大纲不存于 project.json，统一放在 episodes.json 的 index=0 项，避免重复。

### 3.2 episodes.json

index=0 固定为大纲，1 起为正式分集。

```json
[
  {"index": 0, "title": "大纲", "summary": "", "content": "全篇大纲文字...", "char_count": 800},
  {"index": 1, "title": "第1集·xxx", "summary": "一句话梗概", "content": "本集原文...", "char_count": 23000},
  {"index": 2, "title": "第2集·xxx", "summary": "一句话梗概", "content": "本集原文...", "char_count": 21000}
]
```

### 3.3 panels.json

```json
[
  {
    "id": "p001",
    "sort_order": 1,
    "episode_index": 1,
    "episode_title": "第1集·xxx",
    "paperwork": "【外景·黄昏·山路】\n少年跌跌撞撞地跑上山...",
    "prompt": "一位穿蓝色布衣的年轻男子...",
    "video_prompt": "镜头从海面缓缓升起...",
    "dialogue": "",
    "duration": 4.0
  }
]
```

### 3.4 entities.json

```json
[
  {"id": "e001", "entity_type": "character", "name": "哥哥", "aliases": "我", "description": "20岁男性，黑发，学生装", "importance": "major"},
  {"id": "e002", "entity_type": "character", "name": "路人甲", "aliases": "", "description": "背景路人，无特征", "importance": "minor"},
  {"id": "e003", "entity_type": "location",  "name": "旧家客厅", "aliases": "客厅", "description": "日式家庭客厅，暖色调", "importance": "major"},
  {"id": "e004", "entity_type": "location",  "name": "便利店", "aliases": "", "description": "普通便利店，一次性场景", "importance": "minor"}
]
```

`importance` 字段说明:
- `major`: 反复出现、需要图片/音频锚定保持视觉一致性
- `minor`: 只短暂出现，文字描述足够，不需要专门素材

### 3.5 bindings.json

```json
{"p001": ["e001"], "p002": ["e001", "e003"]}
```

### 3.6 variables.json

项目级键值配置，结构 `[{id, category, key, value}]`。

```json
[
  {"id": "v001", "category": "split",  "key": "proposal", "value": "分集讨论方案文字"}
]
```

分类用途:
- `style`: 画风的临时覆盖（可选；默认画风见 prompts.py 的 STYLE 常量）
- `negative`: 负面提示词
- `split`: 分集方案文字 (proposal)
- `custom`: 用户自定义

### 3.7 operations.jsonl

统一操作日志，JSON Lines 格式 (每行一条记录)，所有写命令追加。

```json
{"time": "2026-06-15T10:22:28", "command": "convert", "detail": "107分镜"}
{"time": "2026-06-15T10:25:10", "command": "extract", "detail": "+45实体"}
{"time": "2026-06-15T10:28:33", "command": "bind", "detail": "98分镜有绑定"}
```

用 `drama log` 查看 (倒序显示最近 N 条)。

## 四、LangGraph 工作流

```
raw_text (小说文本或文件路径)
    │
    ▼  split ────── LLM (全文喂, 交互式) → outline + episodes[]
    │               大纲/方案/切分均喂完整原文 (信息不遗漏，需长上下文模型)
    │               切分时 LLM 只返回切割点(比例+边界原句)，Python 精确切割
    │               >30万字硬上限直接中止 (改用 import-episodes 人工分集)
    │
    ▼  convert ──── LLM (json_mode=False) → panels[]
    │               长篇: 逐集调用，注入大纲和前后集 summary 作为上下文
    │               短篇: 直接转换
    │               同一集内多 chunk 并发 (Semaphore 限流, 结果保序)
    │               [{paperwork, dialogue, characters, sort_order}]
    │
    ▼  extract ──── LLM (json_mode=True) ─→ entities[]
    │               返回 {characters, locations, items} object
    │               [{name, aliases, description, entity_type, importance}]
    │
    ▼  bind ─────── 字符串匹配(graph) / LLM精确(CLI) → bindings
    │               {"p001":["e001","e003"], "p002":["e002"]}
    │
    ▼  infer ────── LLM (json_mode=False) → panels[] + prompt + video_prompt
                    多分镜并发 (Semaphore 限流到 8)
                    注入锚定标记: [核心]/[次要]/[参考图]
                    期望 "图片提示词\n===\n视频提示词" 纯文本格式
```

**json_mode 说明**: 只有 extract 和 bind(LLM模式) 使用 `json_mode=True`（返回 JSON object）。
split/convert/infer 均使用 `json_mode=False`，避免 `response_format: json_object` 限制导致纯文本或 JSON 数组输出失败。

**并发说明**: convert 的多 chunk、infer 的多分镜均通过 `asyncio.gather` + `Semaphore(8)` 并发调用 LLM，
gather 结果保序（分镜先后不乱），大幅缩短 100+ 分镜的处理时间。LLM 客户端配置 `max_retries=3` 应对网络抖动。

**两种 bind 模式**:
- `agent run` 全流程: 字符串匹配 (`_text_bind`)，快速、零成本，但有误匹配
- `entity bind` CLI: LLM 精确绑定 (`bind_entities_llm`)，按集分批调用，准确率高

**实体锚定策略 (infer 节点)**:
- `importance=major`: 注入完整描述，提示词强调外观一致性；配 `image_path` 时追加 `<ref:名称>` 占位符
- `importance=minor`: 仅用泛称，不注入描述

**画风 (STYLE)**: 由项目 `prompts.py` 的 `STYLE` 常量统一管理，convert 和 infer 都引用。
改一处即可同时影响分镜叙事基调与绘图提示词。state 可显式传 style 覆盖，默认走 STYLE。

**convert / infer 职责分层**:
- convert (叙事层): 只产出"画面发生了什么"——景别/地点/动作/情绪，分离对话、标记角色；不写运镜/光影/画风术语
- infer (绘图层): 才写构图/光影/运镜/画风，叠加实体锚定，产出绘图工具用的提示词

## 五、CLI 命令

> `drama` 命令安装在 Python Scripts 目录，Windows 首次使用需将该目录加入 PATH，或用完整路径调用。

```bash
drama init <name>               # 创建项目
drama list                      # 列出项目
drama info                      # 项目信息
drama use <id>                  # 切换当前活动项目 (支持 ID 前缀/名称)
drama log                       # 查看操作日志 (operations.jsonl)

drama novel import <file>       # 导入小说 (.txt/.md)
drama novel split --file x.md  # 交互式分集 (全文喂, ≤30万字)
drama novel import-episodes --folder dir  # 导入人工分集 (超长文本)
drama novel episodes            # 查看分集列表 (index/标题/字数/摘要)
drama novel episodes --show 0  # 查看大纲全文
drama novel episodes --show 1  # 查看第1集原文
drama novel convert             # 按集转换分镜 (有分集时自动逐集, chunk 并发)
drama novel convert --episode 2  # 只转换第2集
drama novel convert --file x.txt  # 直接传文件 (短篇无分集)

drama panel list                # 列出分镜
drama panel show <#>            # 分镜详情
drama panel edit <#> --field prompt --value "新提示词"
drama panel add --paperwork "场景描述"
drama panel delete <#>

drama entity list               # 列出实体
drama entity show <name>        # 实体详情
drama entity add "角色" --type character --importance major
drama entity extract            # AI提取实体 (增量去重, 自动判定重要性)
drama entity extract --replace  # 清空后重新提取
drama entity edit <name> --field importance --value major  # 编辑字段
drama entity set-media <name> --image x.png --audio y.wav  # 绑定参考图/音频
drama entity bind               # LLM 精确绑定实体到分镜 (按集)
drama entity bind --episode 1   # 只绑定第1集

drama prompt infer              # AI推理提示词 (并发, 含锚定策略)
drama prompt infer --panel-index 1  # 只推理第1个分镜

drama export                    # 导出图片/视频提示词 (分开存, 喂不同服务端)
drama export --fmt txt         # 纯文本格式

drama variable list             # 列出变量
drama variable set key value    # 设置变量
drama variable get key          # 获取变量

drama agent run                 # 一键全流程 (短篇)
drama agent run --file x.txt   # 传文件全流程

drama git log                   # 版本历史
drama git diff                  # 版本差异
drama git revert <commit>       # 回滚版本
```
