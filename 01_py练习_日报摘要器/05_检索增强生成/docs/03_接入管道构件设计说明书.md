# 接入管道构件设计说明书

## 一、构件定位

将外部文件（PDF / Markdown / Excel / JSON / 扫描件）转化为可检索的标准知识单元，写入 PostgreSQL。

职责边界：**只负责接入链路**，不参与检索。接入与检索通过共享数据库解耦。

---

## 二、接入链路全景

```text
用户上传文件
  │
  ▼ POST /ingestion/uploads
upload_service.save()           → 磁盘存储，记录 ingestion_uploads
  │
  ▼ POST /ingestion/jobs/preview
IngestionService.run_preview()  → 后台任务
  │
  ├─ parse_service.parse()      → LoadedDocument → ParsedDoc
  │    ├─ PdfLoader (fitz)      → 文字提取 + OCR（扫描/图片页）
  │    ├─ MarkdownLoader        → 按 ## 分节
  │    ├─ ExcelLoader (pandas)  → sheet → DataAsset 列表
  │    └─ JsonLoader            → 数据资产 or 普通文本
  │
  ├─ Chunker                    → List[Chunk]（max_chars/overlap）
  ├─ llm_enrich（可选）         → 摘要 / 预设问题
  ├─ doc_identity
  │    ├─ normalize_text()      → 折叠空白
  │    ├─ compute_content_hash()→ SHA256(正文 + domain)
  │    └─ derive_title()        → 手动 > LLM > 首行 > 文件名
  └─ 写入 preview_uri           → 前端轮询展示
  │
  ▼ POST /ingestion/jobs/{id}/commit
commit_service.run()
  ├─ check_duplicate(hash+domain) → 命中已有 active 文档
  │    ├─ on_duplicate=block   → 返回 409（含 existing_id/title）
  │    ├─ on_duplicate=replace → 旧文档置 archived
  │    └─ on_duplicate=new     → 直接写
  ├─ resolve_title()           → 同名时追加 (2)(3)
  └─ db_writer.write()         → INSERT kb_documents + kb_chunks + data_assets
```

---

## 三、API 端点

| 方法 | 路径 | 说明 |
|:--|:--|:--|
| POST | `/ingestion/uploads` | 上传文件，返回 `upload_id` |
| POST | `/ingestion/jobs/preview` | 创建预览任务（后台异步） |
| GET | `/ingestion/jobs/{id}` | 查询任务状态（status/stage/progress） |
| GET | `/ingestion/jobs/{id}/result` | 获取最终入库结果 |
| POST | `/ingestion/jobs/{id}/commit` | 提交入库（支持 `on_duplicate`） |

**commit 请求体**

```json
{
  "on_duplicate": "block"   // block | replace | new
}
```

**409 响应体（block 命中）**

```json
{
  "detail": {
    "existing_id": "doc-uuid",
    "existing_title": "液压泵维修手册",
    "message": "Document with same content already exists"
  }
}
```

## 四、任务状态机

```text
pending → running → completed
                  → error
                  → cancelled（预留）
```

`stage` 字段细化进度：`uploading` → `parsing` → `enriching` → `committing` → `done`

## 五、服务分层

| 服务 | 职责 | 有无 DB 依赖 |
|:--|:--|:--|
| `IngestionService` | 任务生命周期 + 后台任务调度 | 有（任务表） |
| `parse_service` | 文件 → ParsedDoc（无状态函数） | 无 |
| `commit_service` | 去重 / 归档 / 同名序号 | 有（kb_documents） |
| `db_writer` | INSERT kb_documents / chunks / assets | 有 |
| `llm_enrich` | 摘要 / 问题 / 标题（外部 HTTP，可选） | 无 |
| `doc_identity` | normalize / hash / derive_title（纯函数） | 无 |
| `upload_service` | 文件落盘 | 无（本地磁盘） |

## 六、去重与标题优先级

### 指纹规则

```python
content_hash = sha256(normalize_text(full_text) + "|" + business_domain)
```

`normalize_text`：折叠连续空白、去首尾空行，保证同内容不同排版指纹一致。

### 标题优先级

```text
手动输入 > LLM 提取（开启时）> 正文首行 / markdown # 标题 > 文件名 stem
```

### 同名序号

同名且指纹不同时，自动追加 ` (2)` / ` (3)`：

```sql
SELECT title FROM kb_documents
WHERE (title = $1 OR title LIKE $1 || ' (%)')
  AND business_domain = $2
  AND status = 'active'
```

## 七、支持格式与扩展点

| 格式 | 现状 | 扩展方式 |
|:--|:--|:--|
| PDF（文字） | ✅ fitz 文字抽取 | — |
| PDF（扫描/图片） | ✅ OCR 服务（可选） | OCR_API_URL 配置 |
| Markdown | ✅ 按 ## 分节 | — |
| Excel | ✅ 指定 sheet 名 | 扩展 sheet_names 白名单 |
| JSON | ✅ data_asset 列表 or 文本 | — |
| docx / txt / pptx | ❌ 未实现 | 新增 `_parse_xxx`，走同一 `_build_text_chunks` |

## 八、关键约束

- **接入非同步阻塞**：`run_preview` / `run_commit` 均以 FastAPI `BackgroundTask` 运行，API 立即返回 task id。
- **单池**：`commit_service` / `db_writer` 均接受 `pool` 参数，不自建连接。
- **幂等预览**：同一 `job_id` 可多次调用 preview（重新解析），结果覆盖。
- **OCR 降级**：`OCR_API_URL` 为空时跳过，不中断流程。
