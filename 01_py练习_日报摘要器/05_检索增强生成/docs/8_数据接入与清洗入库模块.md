# 数据接入与清洗入库模块

## 一、模块定位

数据接入与清洗入库模块负责将外部知识转化为可检索、可追溯、可更新的标准知识单元。

它不关心最终使用哪种召回方式，也不绑定某个数据库。它只负责产出标准化数据包，由后续索引适配器决定写入 PostgreSQL、pgvector、OpenSearch、Qdrant、Neo4j 或对象存储。

## 二、输入类型

支持的数据输入：

```text
PDF / Word / Markdown / HTML
图片 / 截图 / 扫描件
Excel / CSV
数据库表结构
指标口径说明
API / 工具说明
历史问答案例
人工录入知识
```

## 三、输出对象

清洗后输出统一对象：

```text
Document
Chunk
Asset
DataAsset
Entity
Relation
EmbeddingTask
IndexTask
```

这些对象不直接等于数据库表，而是入库流水线中的标准中间格式。

## 四、标准 Document

```json
{
  "document_id": "doc_001",
  "title": "液压系统维护手册",
  "doc_type": "manual",
  "source_uri": "manuals/hydraulic.pdf",
  "business_domain": "equipment",
  "version": 1,
  "metadata": {
    "department": "设备运维",
    "security_level": "internal"
  }
}
```

## 五、标准 Chunk

Chunk 是最重要的检索单位，必须保证可独立理解。

```json
{
  "chunk_id": "chunk_001",
  "document_id": "doc_001",
  "chunk_index": 3,
  "section_path": "设备维护 > 液压系统 > 压力不足",
  "title_context": "液压系统维护手册 - 压力不足故障排查",
  "content": "当液压泵压力不足时，应优先检查过滤器是否堵塞、油液液位是否正常，以及泄压阀是否异常。",
  "summary": "说明液压泵压力不足时的优先检查项。",
  "preset_questions": [
    "液压泵压力不足怎么办？",
    "液压系统压力不够应该先检查哪里？",
    "过滤器堵塞会导致液压泵压力不足吗？"
  ],
  "physical_context": {
    "page": 18,
    "paragraph": 2,
    "image_refs": ["asset_001"]
  },
  "metadata": {
    "business_domain": "equipment",
    "doc_type": "manual"
  }
}
```

## 六、Chunking 规则

### 1. 切分粒度

```text
每个 Chunk 建议 300-800 中文字
按标题、段落、步骤、条款切分
不要从一句话中间切断
同一操作步骤尽量保持在同一 Chunk
表格和图片需要保留引用关系
```

### 2. 上下文增强

每个 Chunk 的 embedding 文本建议拼接：

```text
title_context
section_path
summary
content
preset_questions
```

拼接格式：

```text
[标题上下文] 液压系统维护手册 - 压力不足故障排查
[章节路径] 设备维护 > 液压系统 > 压力不足
[摘要] 说明液压泵压力不足时的优先检查项。
[正文] 当液压泵压力不足时...
[可能问题] 液压泵压力不足怎么办？...
```

### 3. 预设问题

`preset_questions` 用于增强问题相关性。

要求：

```text
每个 Chunk 2-5 个问题
覆盖口语问法、专业问法、故障问法、操作问法
第一阶段可人工编写
后续可由 LLM 自动生成
```

## 七、标准 Asset

图片、附件、截图统一为 Asset。

```json
{
  "asset_id": "asset_001",
  "document_id": "doc_001",
  "chunk_id": "chunk_001",
  "asset_type": "image",
  "asset_url": "http://localhost:9000/factory/pump_fault_01.png",
  "caption": "液压泵压力异常示意图",
  "ocr_text": "过滤器 压力阀 液压泵",
  "description": "图片展示液压泵、过滤器、压力阀之间的连接关系。",
  "physical_context": {
    "page": 18,
    "bbox": [0.12, 0.2, 0.8, 0.65]
  }
}
```

第一阶段图片可只存 URL、OCR、caption、description。后续再加入图片向量或多模态模型分析。

## 八、标准 DataAsset

表、字段、指标、案例、工具说明统一为 DataAsset。

```json
{
  "asset_id": "asset_metric_sales",
  "asset_type": "metric",
  "name": "销售额",
  "description": "统计周期内已支付订单的实付金额合计，剔除退款订单。",
  "business_domain": "sales",
  "synonyms": ["GMV", "营收金额"],
  "formula": "sum(pay_amount)",
  "related_table": "dwd_order_detail",
  "related_columns": ["pay_amount", "pay_time", "order_status"]
}
```

asset_type：

```text
table
column
metric
case
tool
api
```

## 九、EmbeddingTask

清洗服务不直接假设向量写到哪里，只生成 embedding 任务。

```json
{
  "task_id": "emb_001",
  "object_type": "chunk",
  "object_id": "chunk_001",
  "embedding_text": "...",
  "embedding_model": "bge-m3",
  "target_capabilities": ["vector_search"]
}
```

由索引适配器决定写入：

```text
PostgreSQL pgvector
Qdrant
Milvus
其他向量后端
```

## 十、IndexTask

同一份数据可以进入多个索引。

```json
{
  "object_type": "chunk",
  "object_id": "chunk_001",
  "index_targets": [
    {
      "backend": "postgres_pgvector",
      "capability": "vector_search"
    },
    {
      "backend": "opensearch",
      "capability": "bm25_search"
    }
  ]
}
```

## 十一、入库流水线

```text
采集数据源
  ↓
解析原始文件
  ↓
抽取文本、图片、表格
  ↓
生成 Document
  ↓
语义切分 Chunk
  ↓
生成 summary / preset_questions
  ↓
生成 Asset / DataAsset
  ↓
生成 EmbeddingTask
  ↓
生成 IndexTask
  ↓
交给索引适配器写入不同后端
```

## 十二、容器化设计

容器名称：

```text
ingestion-service
```

职责：

```text
文件解析
文本清洗
Chunking
摘要生成
预设问题生成
OCR 调用
EmbeddingTask 生成
IndexTask 生成
```

不负责：

```text
检索排序
Agent 回答
数据库查询业务逻辑
```

## 十三、接口建议

入库模块可提供通用任务接口：

```text
POST /ingestion/jobs
GET  /ingestion/jobs/{job_id}
POST /ingestion/parse
POST /ingestion/chunk
POST /ingestion/build-index-task
```

这些接口不绑定某个数据库。

## 十四、总结

数据接入与清洗模块只负责把原始资料加工成标准知识对象。它的输出可以被任意数据库和任意召回策略消费。

关键原则：

```text
清洗结果标准化
索引写入可配置
数据库选择后置
召回方式后置
```
