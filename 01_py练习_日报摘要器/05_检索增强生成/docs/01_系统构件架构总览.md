# 系统构件架构总览

## 一、系统定位

面向企业设备运维场景的模块化 RAG 系统。将文档接入、向量存储、检索编排、知识管理、前端交互拆分为独立构件，通过统一的 HTTP API 和共享数据库连接池协作。

---

## 三、构件清单

| 编号 | 构件名 | 进程/端口 | 主要职责 |
|:--|:--|:--|:--|
| C01 | 数据库 | PostgreSQL :5433 | 文档/块/资产存储 + 向量检索 |
| C02 | 后端 API | FastAPI :8000 | 检索编排、接入管道、知识管理统一网关 |
| C03 | OCR 服务 | FastAPI :10001 | 扫描件/嵌入图片文字识别（GPU） |
| C04 | LLM 富化服务 | 外部 API | 摘要/问题/标题提取（可选） |
| C05 | 前端 | Next.js :3000 | 用户界面 |
| C06 | 接入解析库 | 进程内库 | 文件加载、分块（被 C02 调用） |
| C07 | 评估脚本 | CLI | 离线检索质量评估 |

## 四、构件间依赖

```text
C05 前端
  → C02 后端 API（HTTP）

C02 后端 API
  → C01 数据库（asyncpg pool，共享单池）
  → C03 OCR 服务（HTTP，可选，OCR_API_URL 控制）
  → C04 LLM 富化（HTTP，可选，LLM_API_KEY 控制）
  → C06 接入解析库（进程内 import）

C07 评估脚本
  → C02 后端 API（HTTP）

C03 OCR 服务
  → 本地模型文件（<MODELS_DIR>\Unlimited-OCR）
  → NVIDIA GPU（CUDA）
```

## 五、部署方式

### 开发环境（本机）

```bash
# C01
docker compose up -d

# C02
cd backend && uvicorn app.main:app --reload --port 8000

# C03（有 GPU 时启动）
python ocr_service/server.py   # :10001

# C05
cd frontend && npm run dev     # :3000
```

### 生产环境（建议）

| 构件 | 容器化方式 |
|:--|:--|
| C01 | docker compose（已有） |
| C02 | Dockerfile + uvicorn workers |
| C03 | 独立容器，挂载 GPU，挂载模型目录 |
| C05 | Next.js 静态导出 / Node server |

## 六、关键约束

- **单连接池**：C02 全进程共享一个 `asyncpg.Pool`，通过 `app.state.db` 传递，禁止在各 service 内自建连接。
- **OCR 可选降级**：`OCR_API_URL` 为空时跳过 OCR，不影响其他链路；扫描页文字置空，不中断接入流程。
- **LLM 可选降级**：`LLM_API_KEY` 为空时，摘要/标题/问题均走规则兜底。
- **去重语义**：`content_hash = SHA256(归一化正文 + business_domain)`，commit 时默认 block，支持 replace/new 覆盖。
- **检索只读 active**：`kb_documents.status = 'active'` 才参与检索；replaced 旧版本自动归档为 `archived`。
