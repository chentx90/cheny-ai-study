```
commands/asset_production.py # V3 实体档案、视觉风格与资产生成命令

storage.py                 # SQLite（后续可按域拆 mixin，暂保持门面）
```

**视频生成主链路（不要再分叉）：**

1. 路由收请求 → `video_submit.build_video_task_for_*`  
2. `_run_and_store_video_task`：立刻 `processing` 落库并返回  
3. 后台：`prepare_video_assets`（OSS）→ 网关 `/videos` → 轮询下载  

参考素材规范：仅 `https` / `asset://`；本地文件经 `https://oss.vjimeng.vip` 直传；禁止 base64。见 `docs/09`。

## 命令副作用与前端同步

1. 所有 `mutation=True` 命令必须在 `CommandSpec.effects` 声明失效数据域。
2. `CommandBus.execute` 将 `effects` 原样写入统一命令结果；CLI、Agent 和后续 HTTP 调用端共享同一契约。
3. Agent 前端只解析命令结果，不按命令名称猜测刷新行为。
4. `useAgentInvalidation` 负责将 `projects / workspace / entities / assets / asset-production / templates / prompt-cards / videos` 映射到各领域刷新函数。
5. 新增写命令但未声明 `effects` 时，`test_every_mutation_command_declares_frontend_effects` 必须失败。

## 状态生命周期约定

1. 项目切换以项目 ID 作为组件和异步请求作用域；旧项目晚到的响应不得覆盖当前项目。
2. 项目详情并行加载，并以递增请求序号保证“最新选择胜出”。
3. 项目级组件通过 `key={project.id}` 重建局部 UI 状态，禁止用 effect 将旧项目状态补写到新项目存储键。
4. 所有浏览器持久化统一通过 `app/uiStorage.js`，页面和 hook 不直接调用 `localStorage`。
5. Agent 用户消息可以乐观显示，但服务端消息始终是持久化真相源；项目或会话切换后丢弃旧请求回写。
